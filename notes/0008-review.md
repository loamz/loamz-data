# 0008 security and architecture review

14 November 2026. **Decision: sound direction, not ready for a first customer.** A private upstream MLflow behind a Loamz gateway is reasonable, but the gateway is the security boundary, not a transparent proxy. Three-part names alone do not make upstream MLflow a Unity Catalog server. Pin a client/server version and prove each supported client operation against that version before promising compatibility.

## Three ways data leaks

1. **A guessed ID, name, alias, or linked object.** A run ID may belong to another experiment; a model version may reference another run or artifact. Resolve every identifier, including every member of a batch and every source/destination/link, through a server-owned `(organization, workspace, object)` map; check current rights on all referenced objects and dependencies. Bind names and aliases to the workspace. Missing and forbidden both return 404. Never trust a client-supplied owner, experiment ID, artifact URI or trace association.
2. **Search, count, pagination, or errors.** Filtering a page after MLflow computes its counts, ordering, aggregate or cursor can reveal hidden entries; a cursor can be replayed in a different workspace or after revocation. Restrict the upstream query to authorized objects *before* search and aggregation; if impossible, perform these operations over an authorized Loamz index or refuse them. Issue opaque, authenticated cursors bound to identity, workspace, query and authorization epoch; recheck rights on each page. Sanitize errors, counts and metadata, including search filters over hidden values.
3. **A trace or artifact outlives its source rights.** Experiment access alone is not sufficient. Bind every run, model, prompt, trace, assessment, artifact and derived output to its complete trusted provenance and owner; check both the object and all source policies on every read, search, download and link. Unresolved or mixed provenance is private to the creator and inaccessible until resolved; when row filters or masks differ, deny the captured data unless an equally restrictive policy can be enforced on it. Revocation and policy changes take effect on the next request; revoke access to mirror tables and derived artifacts too. Do not expose reusable direct URLs beyond a strictly bounded, documented expiry.

## Candidate client surface; deny by default

These are **endpoint families to inventory, not wildcard forwarding rules**. Expand them into exact method/path, request/response and authorization tests from the pinned client's traffic and protobufs. The current upstream changes; this list is not proof of full compatibility. Prefix `/api` unless shown otherwise. Sources: [MLflow REST reference](https://mlflow.org/docs/latest/api_reference/rest-api.html), [tracking client implementation](https://github.com/mlflow/mlflow/blob/master/mlflow/store/tracking/rest_store.py), [OTLP support](https://mlflow.org/docs/latest/genai/tracing/integrations/listing/langflow).

- **Tracking:** `2.0/mlflow/experiments/{create,get,get-by-name,search,update,delete,restore,set-experiment-tag,delete-experiment-tag}`; `2.0/mlflow/runs/{create,get,search,update,delete,restore,log-metric,log-parameter,set-tag,delete-tag,log-batch,log-inputs}`; `2.0/mlflow/metrics/get-history`; `2.0/mlflow/artifacts/list`. Check run input datasets, logged models and every batch element. Check other logged-model and metric endpoints observed in the pinned client individually.
- **Registry and prompts:** `2.0/mlflow/registered-models/{create,get,search,update,rename,delete,set-tag,delete-tag}` and `2.0/mlflow/model-versions/{create,get,search,update,delete,get-download-uri,set-tag,delete-tag}`; `2.0/mlflow/registered-models/alias` (get/set/delete). Prompts in the OSS client may use registry models, versions, tags and aliases; authorize those calls as prompts too. `catalog.schema.name` is an input name, not proof that upstream implements Unity Catalog. A real UC-configured client may call `/api/2.1/unity-catalog/...` instead: capture its exact model, version, alias and prompt calls and implement and test that protocol separately, or explicitly document that UC client mode is unsupported. Do not forward UC requests to an OSS MLflow endpoint by assumption.
- **Traces and evaluation:** `/v1/traces` POST (OTLP) and the pinned client's `2.0/mlflow/traces` and `3.0/mlflow/traces` create/get/search/delete, trace tags and run/prompt links; `3.0/mlflow/traces/{trace_id}/assessments` and `.../assessments/{assessment_id}` for feedback and expectations. Evaluation runs locally in the client or job and uses runs, metrics, artifacts, traces and assessments; managed evaluation datasets also use `3.0/mlflow/datasets` and `.../datasets/{id}/records`. Inventory exact methods and additional routes from actual pinned-client tests; do not claim all evaluators work merely because these paths exist.
- **Artifacts:** implement `2.0/mlflow-artifacts/artifacts` GET and `2.0/mlflow-artifacts/artifacts/<path>` GET/PUT/DELETE at the gateway over governed volumes; never forward them upstream. Bind the path to a mapped run/model, not a client-selected storage root. Multipart upload routes (`2.0/mlflow-artifacts/mpu/{create,complete,abort}/<path>`) remain denied until a scoped, bounded gateway implementation exists.
- **Never forward:** catch-all or `/ajax-api` UI routes, arbitrary proxy/redirect URLs, MLflow admin/auth, users, credentials, webhooks, serving, deployment, gateway/provider management, jobs, MCP and unreviewed new routes. Refuse upstream presigned artifact/download and multipart credentials (`2.0/mlflow/artifacts/presigned-download-url`, `2.0/mlflow-artifacts/presigned/<path>`); no raw bucket paths, external `source` URIs, local files, network fetches or upstream artifact roots. Gateway-issued narrowly scoped links are a separate, reviewed contract. Any unsupported client feature fails closed and is documented.

## Artifacts, traces and functions

- **Artifacts are untrusted executable content.** Pickle, model loaders, dependency hooks and archives can execute code. The server never imports, unpickles, previews by executing, or auto-serves a model. Loading occurs only in a fresh gVisor job as the caller, with no network or host credentials and only the caller's authorized inputs and outputs; make the danger clear to readers. Prevent traversal and path ambiguity: decode once, reject encoded separators, `..`, absolute paths, NULs, backslashes and symlinks; resolve under the server-chosen object prefix and disallow archive extraction outside it. Stream with hard per-file, total, expanded-size, rate and concurrent-upload quotas; use atomic completion, checksum, timeouts and cleanup of partial uploads.
- **Traces are data.** Capture is opt-in and content off by default; provenance must come from trusted jobs and data access, not OTLP tags. Store no credentials, tokens, keys, authorization headers, session cookies, connection strings or raw secrets anywhere, including attributes, events, errors, logs and mirrors. Apply structured allow-listing/redaction before forwarding or persistence; reject payloads when safe handling is uncertain. Do not promise arbitrary free text can be reliably scrubbed. Restrict content to approved fields with customer-defined retention and erasure across MLflow, mirrors, artifacts and backups. Mirror only into tables whose access enforces the same per-trace provenance, row filters and masks; otherwise use isolated per-policy tables or do not mirror. Provenance-free external OTLP remains private, not automatically shareable.
- **Functions:** `EXECUTE` permits invocation, never grants data access. Bind a versioned function definition and declared inputs/outputs; the server resolves dependencies and narrows the caller's own job token, rechecking caller, agent and current policies at submit, lease, each access and result retrieval. No owner/service-account elevation; deny dynamic or undeclared access and treat Python dependencies as untrusted. Python reads only governed query results with row filters and masks, never raw table folders when policy applies. Enforce fresh gVisor sandbox, no network or host credentials, CPU/process/disk limits, cancellation and per-org quotas. Initial hard ceilings: 60 seconds wall time, 1 GiB RAM, 4 MiB returned output, bounded logs and 1 GiB scratch; operators may lower them, and larger limits need explicit reviewed configuration. Recheck declared writes and output release under caller rights.

## First-customer gates

- Prove isolation with two organizations, workspaces and differently permitted people: guessed IDs, aliases, cross-object links, batch/search/count/pagination, OTLP injection, malicious paths and model files, policy changes/revocation, partial writes and direct upstream access. Include row filters/masks, stale cursors, erasure and concurrent mutation. Test the pinned stock client end to end; establish a recorded compatibility matrix and upgrade review.
- MLflow and Loamz have separate databases: no shared atomic transaction. Use a durable Loamz operation/audit state machine with idempotent upstream actions, reconciliation, retries and fail-closed visibility; exercise crashes at every step. Back up and restore both consistently with volumes, and make drop/erase durable across all copies. Audit without recording content or secrets.
- Network isolation and service authentication must prevent direct MLflow, its database and its internal artifact endpoints from being reached by clients or sandbox jobs. Encrypt in transit and at rest, restrict upstream outbound network and file access, pin/patch images and dependencies, and define incident response, quotas and retention. The planned sandbox and data-write capabilities in 0006/0005 must pass their own gates first; they are not all built today.
- A networkless sandbox cannot call a remote model judge or the MLflow gateway itself. Define a narrowly scoped, policy-checked broker and approved egress for external evaluation, or support only local evaluators; do not silently grant network access or send customer data to a model provider.
